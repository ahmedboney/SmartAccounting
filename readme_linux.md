# تشغيل النظام على Linux

## المتطلبات

- Linux (مثل Ubuntu أو Debian)
- Python 3.10 أو أحدث
- اتصال بالإنترنت عند أول تشغيل لتثبيت الحزم

على Ubuntu/Debian ثبّت المتطلبات الأساسية:

```bash
sudo apt update
sudo apt install python3 python3-venv
```

## التشغيل

من داخل مجلد المشروع:

```bash
chmod +x run.sh
./run.sh
```

ينشئ السكربت بيئة Python محلية في `.venv`، ويثبت الحزم الموجودة في `requirements.txt`، ثم يشغل النظام. افتح:

```text
http://localhost:5000
```

في أول تشغيل تُنشأ قاعدة البيانات داخل `instance/` تلقائيًا.

لإيقاف النظام اضغط `Ctrl+C` في الطرفية التي يعمل بها السكربت.

## تشغيل بدون سكربت

يمكن تشغيل النظام يدويًا بعد تفعيل البيئة الافتراضية:

```bash
source .venv/bin/activate
python app.py
```

## الوصول من أجهزة أخرى على الشبكة

يعرض النظام على جميع واجهات الشبكة. افتح من جهاز آخر:

```text
http://IP-الجهاز-الرئيسي:5000
```

لمعرفة عنوان الجهاز الرئيسي:

```bash
hostname -I
```

إذا كان جدار الحماية مفعّلًا، اسمح بالمنفذ 5000 على الشبكة المحلية فقط، مثلًا مع UFW:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 5000 proto tcp
```

استبدل `192.168.1.0/24` بنطاق شبكتك. لا تفتح المنفذ للإنترنت العام إلا بعد تأمين الراوتر والنظام.

## بيانات الدخول الافتراضية

- `admin / admin123`
- `ahmed / ahmed123`
- `viewer / viewer123`

غيّر كلمات المرور من الإعدادات فورًا.

## النسخ الاحتياطي والترقية

- انسخ مجلد `instance/` دوريًا؛ يحتوي قاعدة SQLite والنسخ الاحتياطية.
- لاستعادة قاعدة بيانات، استخدم صفحة الإعدادات داخل النظام.
- لترقية قاعدة قديمة من الكود شغّل:

  ```bash
  .venv/bin/python app.py --upgrade
  ```

## حل المشاكل الشائعة

### `No module named venv`

ثبّت دعم البيئة الافتراضية ثم أعد التشغيل:

```bash
sudo apt install python3-venv
```

### المنفذ 5000 مستخدم

شغّل النظام على منفذ آخر:

```bash
PORT=5001 ./run.sh
```

ثم افتح `http://localhost:5001`.

### صلاحية تشغيل السكربت

نفّذ مرة واحدة:

```bash
chmod +x run.sh
```
